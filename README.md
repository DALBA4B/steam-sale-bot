# steam-sale-bot

Раз в день присылает в Telegram список игр из твоего вишлиста Steam, на которые сейчас есть скидка: название, процент, цена до и после в гривнях и сколько скидка ещё идёт.

Пример сообщения:

```
🎮 Скидки на вишлист · 27 августа
Со скидкой: 35 из 375 · новых: 4

🆕 -75% Red Dead Redemption 2
   2 599,00₴ → 649,00₴ · до 8 сент., 20:00

-60% Dead by Daylight
   429,00₴ → 171,00₴ · ⏳ до 30 авг., 20:00 (осталось ~19 ч)

-38% How to Fish
   159,00₴ → 98,00₴ · идёт 3-й день
```

Каждый прогон присылает **весь текущий список**, а не только новинки: так видно, что скидка ещё идёт. Новое с прошлого раза помечается 🆕 и уходит наверх.

## Что нужно

- Node.js 20+ (зависимостей нет вообще, всё на встроенном `fetch`)
- бот от [@BotFather](https://t.me/BotFather) и его токен
- список appid из вишлиста

Пароль от Steam не нужен и никогда не понадобится.

## Установка

1. **Список игр.** Открой попап расширения [T-igruha-to-Steam-Wishlist](https://github.com/DALBA4B/T-igruha-to-Steam-Wishlist), нажми «Скачать JSON» и положи файл рядом как `games.json`. Формат свободный: массив чисел, массив объектов с полем `appid` или выгрузка расширения как есть — см. `games.example.json`.

2. **Настройки.** Скопируй `.env.example` в `.env` и заполни:

   ```
   TG_TOKEN=токен от BotFather
   TG_CHAT_ID=твой chat id
   ```

   `chat_id`: напиши боту любое сообщение, открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьми `"chat":{"id":...}`.

3. **Проверка без отправки:**

   ```
   node src/index.js --dry
   ```

   Печатает готовое сообщение в консоль. Ничего никуда не уходит.

4. **Отправить в Telegram:**

   ```
   node src/index.js
   ```

## Как запускать по расписанию

Два варианта.

**Свой процесс (подходит для Railway с постоянным запуском и для VPS):**

```
node src/index.js --loop
```

Процесс висит и сам отправляет в 20:30 по Киеву. Время считается через `Intl`, поэтому переход на зимнее время учитывается автоматически.

**Cron.** На Railway в настройках сервиса укажи Cron Schedule `30 17 * * *` (это 20:30 по Киеву летом, зимой будет 19:30 — потому и рекомендую `--loop`), команда `node src/index.js`.

Почему раз в день, а не раз в неделю: Daily Deals живут сутки, а Midweek/Weekend — два-три дня, при недельной проверке половина скидок проходит мимо.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `TG_TOKEN` | — | токен бота, обязателен |
| `TG_CHAT_ID` | — | куда писать, обязателен |
| `STEAM_CC` | `UA` | регион цен, отсюда гривни |
| `STEAM_LANG` | `english` | язык названий игр |
| `MIN_DISCOUNT` | `1` | порог в процентах, `1` = любая скидка |
| `SEND_HOUR` / `SEND_MINUTE` | `20` / `30` | время отправки в режиме `--loop` |
| `TZ_NAME` | `Europe/Kyiv` | часовой пояс для времени и дат |
| `GAMES_FILE` | `./games.json` | путь к списку appid |
| `STATE_FILE` | `./state.json` | путь к файлу состояния |
| `MAX_ITEMS` | `0` | обрезать список в сообщении, `0` = все |
| `NOTIFY_ERRORS` | `1` | присылать в чат сообщение, если прогон упал |

Локально всё это живёт в `.env` (в git не попадает). На Railway — в переменных сервиса.

## Деплой на Railway

1. Залей репозиторий на GitHub, подключи его в Railway.
2. В Variables добавь `TG_TOKEN` и `TG_CHAT_ID`, при желании `MIN_DISCOUNT`.
3. Start Command: `node src/index.js --loop`.
4. `games.json` в репозиторий не коммитится (личный список), поэтому либо залей его вручную через том, либо положи содержимое в переменную и поправь `GAMES_FILE`. Проще всего — том Railway и в нём `games.json` + `state.json`.

Важно про состояние: файловая система контейнера на Railway пропадает при редеплое. Без тома `state.json` обнулится, и в первом сообщении после редеплоя все скидки будут помечены 🆕. Ошибка безобидная, но том это лечит.

## Файлы

```
src/config.js     — чтение .env и все настройки, проверка обязательных переменных
src/steam.js      — загрузка appid из файла и цены через IStoreBrowseService/GetItems
src/state.js      — что видели в прошлый раз: 🆕 и «идёт N-й день»
src/format.js     — сборка HTML-сообщения, сортировка, нарезка по лимиту 4096
src/telegram.js   — sendMessage, getMe
src/index.js      — точка входа, режимы --dry и --loop, уведомление об ошибке

tools/chat-id.js         — показать свой chat_id (токен в вывод не попадает)
tools/resolve-missing.js — попытка найти appid для записей без него, результат ненадёжен
```

Список игр берётся из файла: `games.json`, `game.json` или `wishlist-items.json` — что найдётся первым. Записи без `appid` (статусы `skipped`, `ambiguous`, `notfound`) в дайджест не попадают.

Подробности для доработки — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Безопасность

- токен и chat_id только в `.env` и в переменных Railway, в коде их нет;
- `.env`, `games.json` и `state.json` в `.gitignore`;
- запросы уходят только на `api.steampowered.com`, `store.steampowered.com` и `api.telegram.org`;
- в текст ошибок токен не подставляется.
