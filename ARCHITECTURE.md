# Как это устроено

Документ для того, кто будет доделывать проект (человек или другая модель). Коротко: что где лежит, какие решения уже приняты и почему, и на какие грабли не наступать заново.

## Задача одной фразой

Раз в день собрать по списку appid текущие цены в Steam, оставить те, где есть скидка, и прислать это в Telegram одним сообщением с процентом, ценой до/после и сроком скидки.

## Жёсткие ограничения

1. **Никогда не запрашивать логин, пароль или Steam Guard.** Всё, что делает бот, доступно без авторизации. Если задача выглядит так, что нужен вход в аккаунт, — задача поставлена неверно.
2. **Токен Telegram только в окружении.** Ни в коде, ни в README, ни в сообщениях об ошибках. `src/telegram.js` намеренно не подставляет URL с токеном в текст исключения.
3. **Никаких зависимостей.** Node 20+ умеет `fetch` и читать файлы, `.env` парсится вручную в `src/config.js`. Не тащить dotenv/axios/node-telegram-bot-api.
4. **Не давить на Steam.** Батч 200 appid, пауза 500 мс между батчами, ретраи с задержкой на 429 и 5xx.

## Эндпоинт цен: почему именно этот

Проверено живьём в августе 2026:

| Что пробовали | Итог |
|---|---|
| `appdetails?filters=price_overview` | `{"success":true,"data":[]}` — пусто |
| `appdetails` без фильтров | `price_overview: null` даже у платных игр |
| `IWishlistService/GetWishlist/v1` без ключа | `{"response":{}}` |
| `wishlist/profiles/<id>/wishlistdata` | отдаёт HTML, эндпоинт мёртв |
| `api/storesearch` | работает, но ищет по названию — возвращает риск неверного совпадения |
| **`IStoreBrowseService/GetItems/v1`** | **работает по appid, батчами, без ключа** |

Рабочий запрос:

```
GET https://api.steampowered.com/IStoreBrowseService/GetItems/v1/?input_json={
  "ids": [{"appid": 1174180}, ...],
  "context": { "language": "english", "country_code": "UA", "steam_realm": 1 },
  "data_request": { "include_assets": false }
}
```

Всё нужное лежит в `store_items[].best_purchase_option`:

- `final_price_in_cents`, `original_price_in_cents` — числа в копейках, приходят строками;
- `formatted_final_price`, `formatted_original_price` — уже с ₴ и пробелами разрядов, их и печатаем, чтобы не форматировать валюту самим;
- `discount_pct` — процент;
- `active_discounts[0].discount_end_date` — unix-время конца скидки, есть почти всегда;
- `best_purchase_option` отсутствует у бесплатных игр, ещё не вышедших и снятых с продажи — такие просто выпадают из выборки.

Батч 200 отвечает за ~0.5 с, так что 375 игр это два запроса и меньше двух секунд.

```
games.json (appid)
```

## Состояние

`state.json`:

```json
{ "seen": { "1174180": { "pct": 75, "firstSeen": "2026-08-27" } }, "lastRun": "..." }
```

Зачем оно нужно: пометить 🆕 и посчитать «идёт N-й день», когда `discount_end_date` не пришёл. Дедупликация не нужна — по решению пользователя каждый прогон присылает весь текущий список, чтобы было видно, что скидка ещё идёт.

Правило сравнения: та же скидка = тот же `pct`. Сменился процент — считаем сделкой новой и снова ставим 🆕, потому что это действительно другое предложение. Игры, вышедшие из скидки, из `seen` удаляются, иначе файл растёт бесконечно.

Пишем состояние **после** отправки. Иначе упавшая отправка съест метки 🆕: в следующий прогон скидки уже считались бы старыми.

## Формат файла со списком игр

Выгрузка расширения — это **объект**, а не массив, и ключ у него это id страницы на игрухе. Внутри записи лежат сразу три числа, похожих на appid:

```json
"13": { "appid": 379430, "id": "19", "slug": "987900", "status": "added",
        "query": "Kingdom Come Deliverance", "candidates": [...] }
```

Брать можно **только `appid`**. Первая версия загрузчика падала на `id` при `appid: null` и на ключ объекта — получилось 470 «appid» вместо 418, причём два id игрухи совпали с реальными appid Steam, и в дайджест попали чужие игры. `loadAppIds()` теперь при наличии ключа `appid` в записи не смотрит больше ни на что.

Статусы в выгрузке: `added`, `already` — с appid, годятся; `skipped`, `ambiguous`, `notfound` — `appid: null`, и в дайджест не попадают. На 474 записях это 418 уникальных appid.

## Ловушки

Каждый пункт — уже совершённая ошибка или проверенная особенность, не откатывать.

- **`parse_mode: 'HTML'`, а не MarkdownV2.** В названиях игр живут `-`, `.`, `!`, `(`, `+`, которые MarkdownV2 требует экранировать; в HTML достаточно `& < >`, это и делает `esc()`.
- **Цены печатать из `formatted_*`.** Свой форматтер гривны неизбежно разойдётся с тем, что видно в магазине.
- **Числа приходят строками.** `final_price_in_cents: "64900"` — везде `Number()`.
- **Лимит Telegram 4096 символов**, режем по 3900 и только по границе игры, не посередине строки.
- **Между сообщениями пауза 1.2 с** — иначе на длинном списке прилетит 429 от Telegram.
- **`msUntilNextRun()` считает через `Intl`,** а не прибавлением 3 часов к UTC. Киев переходит на зимнее время, фиксированное смещение сломается в конце октября.
- **Cron на Railway работает в UTC** и о переходе не знает — поэтому в README режим `--loop` рекомендован основным.
- **Файловая система Railway не постоянная.** Без тома `state.json` умирает при редеплое, и весь список приходит с 🆕. Не баг, но в README про это сказано.
- **Порог `MIN_DISCOUNT=1`, а не 0.** При 0 в список полезли бы игры с `discount_pct: 0`, у которых просто известна цена.
- **`--dry` не должен отправлять ничего,** включая уведомление об ошибке. Проверка стоит в `reportError()`.

## Что где править

| Задача | Файл |
|---|---|
| Изменить вид сообщения, порядок, эмодзи | `src/format.js` |
| Другой регион/валюта, порог, время | `.env`, значения по умолчанию в `src/config.js` |
| Поддержать новый формат списка игр | `loadAppIds()` в `src/steam.js` |
| Другой канал доставки (почта, Discord) | новый модуль рядом с `src/telegram.js`, вызов в `src/index.js` |
| Логика 🆕 и «N-й день» | `src/state.js` |

## Вспомогательные скрипты

- `tools/chat-id.js` — печатает `chat_id` через `getUpdates`. Читает токен из `.env` и **не выводит его**: так узнают, куда писать, не пересылая токен третьим лицам. Перед запуском нужно написать боту любое сообщение, иначе `getUpdates` пуст.
- `tools/resolve-missing.js` — разовая попытка догадаться об appid для записей без него. **Результат ненадёжен**, проверено: `Minecraft` → Minecraft Dungeons, `The Witcher 4` → набор картинок для GWENT, `Death Stranding` → вторая часть. Файл `extra.suggested.json` нельзя подключать без ручной проверки, а лучше не подключать вовсе.

## Как получить полный список игр (обсуждено, не реализовано)

Задача: в файле выгрузки нет appid для 52 записей, а часть этих игр пользователь добавил в вишлист вручную, так что дайджест их не видит.

- **Steam Web API key — отклонён.** Ключ сейчас выдают только при включённом мобильном аутентификаторе и потраченных $5 на аккаунте. Пользователь не хочет заводить двухфакторку, и это решение уважаем: заново предлагать ключ не нужно.
- **Рабочий путь без ключа и паролей:** в браузере, где пользователь уже залогинен, `store.steampowered.com/dynamicstore/userdata/` отдаёт для текущей сессии поле `rgWishlist` — массив appid. Ключ не нужен, профиль может быть закрытым. План: добавить в расширение [T-igruha-to-Steam-Wishlist](https://github.com/DALBA4B/T-igruha-to-Steam-Wishlist) кнопку «Скачать appid вишлиста», а файл кладётся в папку бота. Если Steam закроет этот адрес — собрать appid прямо из разметки страницы вишлиста.
- Сервером это делать нельзя ни в каком виде: сессия Steam живёт в браузере, и логин/пароль для этого запрашивать запрещено (см. ограничение №1).

## Решения по виду сообщения

- **Зачёркивание старой цены убрано** по просьбе пользователя: было `<s>360,00₴</s> → 36,00₴`, стало `360,00₴ → 36,00₴`. Обратно не возвращать.
- **Время отправки 20:30 по Киеву не случайное.** Steam меняет витрину около 10:00 по Тихоокеанскому времени, это ровно 20:00 по Киеву, и оба пояса переходят на зимнее время синхронно, так что 20:00 держится весь год. Видно и по данным: почти все скидки заканчиваются в 20:00 по Киеву. Полчаса форы — чтобы витрина точно успела обновиться.

## Что осталось нерешённым

- **Источник списка игр — файл, а не живой вишлист.** Варианты и почему выбран такой — в разделе выше.
- **Нет ретрая отправки в Telegram при 429** с чтением `retry_after` — сейчас просто падаем и уведомляем.
- **Нет тестов.** Проверка ручная: `node src/index.js --dry`.
- **Не отслеживаются исторические минимумы.** «Лучшая цена за всё время» потребовала бы хранить историю цен в `state.json`.
- **DLC и издания не группируются:** если в вишлисте и базовая игра, и Deluxe, придут обе строки.
